### Task 0 (backend): content stats, moments moderation, user create/edit
**Files:** `controllers/adminContent.js` (add `getContentStats`, `listMoments`, `setMomentHidden`), `controllers/admin.js` (add `createUser`, `updateUser`), `routes/admin.js` (routes below), `test/adminContent.moments.test.js`, `test/adminUsers.create.test.js` (mongodb-memory-server, controller-level like existing admin tests — read `test/admin*.test.js` for the harness).
**Contracts:**
- `GET /api/v1/admin/content/stats` → `{ success, data: { moments: { total, today, last7d, hidden }, comments: { total, last7d }, clubs: { active, archived, membersTotal }, gatherings: { upcoming, past, cancelled }, reports: { pending, underReview, byType: { moment, comment, user, club, gathering, message, story } } } }` — one `Promise.all` of `countDocuments`; `Moment.isDeleted` = hidden.
- `GET /api/v1/admin/content/moments?page&limit&reported&q&hidden` → `{ success, total, page, data: [{ id, title, description (≤ 200 chars), imageUrl (first image or null), language, category, user: { id, name, image }, likeCount, commentCount, viewCount, shareCount, openReports, isDeleted, createdAt }] }` sorted `createdAt` desc; `q` matches title/description regex (escaped); `reported=true` → only `openReports > 0` (same `openReportCounts` helper the club list uses); `hidden=true|false` filters `isDeleted`.
- `POST /api/v1/admin/content/moments/:id/hide` body `{ hidden: boolean, reason?: string }` → sets `isDeleted`, writes `AdminAuditLog` action `moment.hide` / `moment.unhide`, returns `{ success, data: { id, isDeleted } }`; 404 for unknown id.
- `POST /api/v1/admin/users` body `{ name, email, password, gender, birth_year, birth_month, birth_day, native_language, language_to_learn, role?: "user"|"admin", bio?, markVerified?: boolean (default true) }` → same required-field and different-languages checks as `exports.register` in `controllers/auth.js` (factor a shared `validateRegistration(body)` helper into `utils/registration.js` used by both so they cannot drift), creates the user with the hashed password path the model already uses, sets `isEmailVerified`/equivalent when `markVerified`, never returns tokens, writes `AdminAuditLog` action `user.create` with the target id, responds `201 { success, data: { id, name, email, role } }`; 409 on duplicate email.
- `PUT /api/v1/admin/users/:id` body subset of `{ name, bio, native_language, language_to_learn, gender, vip: { grant: boolean, days?: number } }` → updates allowed fields only (whitelist), `vip.grant` sets `userMode: 'vip'` + `vipSubscription.isActive/startDate/endDate` (read the model's own `activateVip`-style method around line 1400 and reuse it) or reverts to `regular`; `AdminAuditLog` action `user.update` with the changed keys; returns the updated safe user (no password/tokens).
- [ ] TDD each contract (shape, filters, audit log entry, 404/409/400 paths); `npm test | tail -14` (one pre-existing failure: authSecretRotation); commit `feat(admin): content stats, moment moderation, admin user create and edit`.
