# BananaTalk 2.4.0

**Theme:** Daily Matches — a new Community layout built around meeting the right partner every day.

## What's new (visible only when the server enables it — ships dark)
- **Matches tab:** six partners chosen for you every day — reciprocal language pairs first — with the reason each one was picked, a one-tap "Say hi", wave, and skip.
- **Partners tab** (was "All") with new segments: 🔥 Serious learners, 🌱 New members. Smart relevance ordering when enabled.
- **Conversation starters:** opener chips in empty chats and a gentle nudge when a chat stalls.
- Simplified Community tabs: Matches · Partners · Gatherings · Rooms · Nearby · Topics · Waves.

## Fixes
- Photo stories now send their privacy setting, caption, colors, and link sticker (photo stories previously posted with the default audience).
- Moment detail, user moments, and comment lists now authenticate, so like/save state and blocked-user filtering work there.
- Reporting a room message now reaches the server (the old endpoint never existed).
- Smart-sort pagination no longer mixes orderings between pages.
- Wave buttons on Nearby/City/Topics/Gender send a single wave and surface "already waved" instead of silently sending a duplicate 👋; the waves badge shows the real unread count.
- Room moderation: member list works; messages from banned users are filtered.
- Voice rooms: scheduled rooms now schedule; creating a room without a category no longer fails.
- Gatherings: pending requests no longer take seats; "Requested" state shows correctly.
- Many backend security fixes (room socket access, story privacy, anonymous answers, DM-share block bypass) — no app change needed.
- Honest copy: the Matches refresh time is shown in local time; the Serious-learners hint no longer over-promises.
- VIP fallback prices aligned with store pricing ($3.99 / $24.99); quarterly plan hidden.

## Server flags this build understands
`matchesLayoutEnabled` (new layout), daily matches endpoint (`DAILY_MATCHES_ENABLED`), `smartSortEnabled`. All default off; the app behaves exactly like 2.2.4 until they are turned on.

## Rollout
1. Backend already deployed (all additive).
2. Submit this build; on approval turn on `DAILY_MATCHES_ENABLED` and `MATCHES_LAYOUT_ENABLED`.
3. `SMART_SORT_ENABLED` only after 2.4.0 is the majority build (it changes 2.2.4's list order).
