# 2.7.0 handoff: steps on the keystore MacBook, Android first

The release notes are in `2.7.0.md`. The procedure is the same as `2.6.1-handoff.md`; only the differences are listed below. The checklist comes from the Android release audit of 2026-10-13.

## 0. Deploy order (before the build reaches users)
Deploy in this order: **backend → web admin → app.** If the new app runs against the old backend, `/announcements/:id` and `/calls/:id/upgrade` return 404, and decline messages are silently dropped. After the backend deploy, confirm that `announcement_once_per_user` is indexed (see `docs/REMAINING_WORK.md`, Release).

## 1. Code
```bash
git fetch origin && git checkout main && git pull --ff-only
cd bananatalk_app && flutter pub get
grep '^version' pubspec.yaml            # 2.7.0+10580
```
After the build is accepted, tag it `v2.7.0` (house convention). The tag is not created yet.

## 2. Build
Always use `flutter build`, never bare Gradle. `android/app/build.gradle` reads the version code from `local.properties`, and only `flutter build` writes that file. Without it, Gradle falls back to `10501`, which is lower than the live code.
```bash
ls android/key.properties                # must exist on this machine
flutter build appbundle --release -Porg.gradle.java.installations.paths=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
```
Then check the signed bundle:
- `versionCode 10580` / `versionName 2.7.0` (use `bundletool dump manifest --bundle build/app/outputs/bundle/release/app-release.aab`).
- No `uses-implied-feature` is required, and none of the removed permissions are present.
- The bundle is signed with the upload key.
- Keep `build/app/outputs/mapping/release/mapping.txt`.

## 3. Release-mode device smoke (R8 has been on since 2.6.1, and this is still the first release-mode run)
Use a Play **internal testing** track, so that Play's own signing is what you test. Check each of these:
1. Incoming call while the app is killed and the phone is locked. You should see the full-screen UI. Accept and Decline must work, both from the CallKit screen and from the notification (the CallKit permission is now `signature`).
2. Two-way audio and video. Background the app: the call survives and the notification is shown. Hang up.
3. Turn the camera on during a voice call. Have the peer turn on their camera: your audio should stay on the earpiece.
4. Kill the app during a video call and reopen it. The call rejoins with the camera off and no forced speaker.
5. Missed-call notification after a ring-out, with the push delayed. Exactly **one** notification should appear, and Call back and Message must work from a killed app.
6. Background push (chat): it should show as a heads-up banner with the white chat-bubble icon. The channel listed in system settings should be "High Importance Notifications".
7. VIP sandbox purchase, then Manage Subscription. It should open Play's subscription page.
8. Rewarded ad, biometric login (Android 7–8 and 13+), QR scan, reel upload (video_compress), and the deep link `bananatalk://`.
9. Pick a photo or video for a moment, story, chat and avatar, on Android 13+ and on Android 9 (READ_MEDIA_* is removed).
10. A Bluetooth headset during a call on Android 12+. If the headset cannot be selected, BLUETOOTH_CONNECT needs a runtime request (open item).
11. Backup: `adb shell bmgr backupnow com.bananatalk.app`, then restore on a fresh install. The app should start logged out, with no biometric error.

## 4. Play Console (required before review)
1. **App content → Foreground service permissions.** Declare **Microphone**, **Camera** and **Phone call**, each as "ongoing user-initiated 1:1 voice/video call". Attach a short screen recording of a call that keeps going after the app is backgrounded, with the "Call in progress" notification visible. Microphone and camera are new since 2.6.1, and the upload is rejected without them.
2. **App content → Full-screen intent.** Declare it as "calling: incoming voice/video calls". The app already copes if Play does not grant it (`FullScreenIntentPrompt`).
3. **Photo & video permissions.** READ_MEDIA_IMAGES/VIDEO were removed in 2.7.0, so withdraw that declaration once 2.7.0 is live.
4. **Data safety.**
   - Recheck it: contacts and phone state are no longer requested.
   - Location (approximate and precise), audio, photos/videos, device IDs (AD_ID from AdMob) and app activity (Firebase Analytics) are still collected.
5. **Advertising ID:** answer "Yes". `com.google.android.gms.permission.AD_ID` is merged in from AdMob/Analytics.
6. **Store listing:** VIP is priced at **monthly $3.99 / yearly $24.99**, and must match the app's fallbacks.
7. **Staged rollout:** start at 10–20 %. Watch Android vitals for R8-related crashes for the first 24 h.

## 5. Web (App Links)
- Get the **upload-key** SHA-256 and the **Play app-signing** SHA-256 from Play Console → App integrity → App signing.
- Paste both into the web repo's `public/.well-known/assetlinks.json`. The live file still holds `TODO_SHA256_*`. Deploy.
- Run `adb shell pm verify-app-links --re-verify com.bananatalk.app`, then `adb shell pm get-app-links com.bananatalk.app`. It should report `verified`.
- The app now claims only `/moment/`, `/profile/`, `/community/` and `/i/`.
