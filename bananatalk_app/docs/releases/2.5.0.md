# BananaTalk 2.5.0

**Theme:** Retention — the first week after signup, done properly.

## What's new (visible only when the server enables it — ships dark)
- **New users land on Matches** — the first screen after sign-up is the daily matches list, not an empty Partners grid (`matchesLayoutEnabled`).
- **Welcome wave** — every new member gets a real wave from an active partner within minutes of completing their profile (`WELCOME_WAVE_ENABLED`, backend only).
- **Day 1 / 3 / 7 nudges** — "your matches are ready", "a partner is online now", "n people waved at you" — push and email, in the member's language, respecting each person's notification preferences and quiet hours (`LIFECYCLE_PUSH_ENABLED`, backend). Tapping one opens the right place: Matches, the partner's chat, or Waves.
- **Invite friends** — a personal invite code and share sheet in the profile menu; when a friend joins with the code and completes their profile, both get coins (`referralsEnabled`).
- **Notification permission at the right moment** — the app asks only after the first match or wave arrives, not on the splash screen (one ask, ever).
- **Review prompt** — after a real two-way conversation (3+ messages each way), at most once every 60 days.

## Fixes
- Deep links that target a Community sub-tab (push taps, `banatalk.com/community/matches|waves`) now land on the right tab even when the app was closed.

## Server flags this build understands
`matchesLayoutEnabled`, `referralsEnabled` (new). `WELCOME_WAVE_ENABLED` / `LIFECYCLE_PUSH_ENABLED` are backend-only. All default off; the app behaves exactly like 2.4.0 until they are turned on.

## Rollout
1. Backend tranche B already deployed dark (backend `c17606b`).
2. Submit this build; on approval set `WELCOME_WAVE_ENABLED=true`, `LIFECYCLE_PUSH_ENABLED=true`, `REFERRALS_ENABLED=true` (plus the 2.4.0 flags if not yet on).
3. Verify: a fresh sandbox signup receives a welcome wave within 1 minute; the next hourly lifecycle run logs sends; `/referrals/me` returns a code.
4. Known gap: `banatalk.com/i/<code>` has no web handler / universal-link entitlement yet — the share text includes the plain code, which works today.
