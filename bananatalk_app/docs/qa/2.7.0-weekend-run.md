# 2.7.0 device test run (before rollout)

One page to run from. Detail lives in the three matrices; this sheet sets the order, the setup, and holds the
release-smoke rows that belong to no matrix. Re-checked against the code on 2026-10-15 (app `main` 5873205a).
Record: date, build, device/OS, tester, pass/fail + note.

## 0. Before you start

- **Build:** signed 2.7.0 (10580) from `main`, uploaded to the Play **internal testing** track (R8 + Play signing is what ships).
  iOS: TestFlight build after the `Podfile.lock` commit (REMAINING_WORK owner step 9).
- **Devices:** iPhone (Face ID); Android 13+ on gesture nav; Android 15 on 3-button nav if possible; Android 8 or 9;
  a Xiaomi or Samsung for Doze rows; a 320-wide emulator; a Bluetooth headset.
- **Accounts:** two calling accounts (A, B) + a second device for B (S-5/S-6, IOS-5); one non-VIP with ≥ 80 coins; one VIP;
  one fresh signup per section-1 onboarding run; a 2.6.1 store build on a spare device (S-12, CALL2-6, CALL2-11).
- **Server flags for the dark features** (prod is all off). Only flip what a section needs, and turn it back off before rollout:
  - AI Study hub rows: `STUDY_HUB_ENABLED` (and `STUDY_VIP_ONLY_FEATURES=photo` for row 2.5) — `study-hub-matrix.md` §0.
  - Onboarding Matches rows: `MATCHES_LAYOUT_ENABLED` — **local backend only**: the live 2.6.1 reads it too, so a prod flip launches it for everyone.
- **Analytics rows:** Firebase DebugView (`adb shell setprop debug.firebase.analytics.app com.bananatalk.app`; iOS `-FIRDebugEnabled`).
