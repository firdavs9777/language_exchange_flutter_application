# Moments audit: web vs app vs backend (read-only)

**Bottom line:** the web calls no backend endpoint that 404s. The biggest risks are:
- a story share link that goes to a domain we don't own
- voice notes recorded on web that probably won't play in the iOS app
- story stickers on web text stories that the app never draws

**What was compared:**
- Web: `language_exchange_web_front`, working tree on local `main`, which has 23 commits not pushed to origin.
- App: `bt-integration/bananatalk_app` at `main` b65c9e3f.
- Backend: `be-integration` at `main` 232fb49, taken as what is deployed.

**How to read the table:**
- Paths start at each repo's root.
- "Unpushed" means the web side is fixed only in the 23 commits that are on local `main` but not on `origin/main`.
- "App branch" means the unmerged app branch `fix/moments-stories-audit` already covers it.
- Every P0 and P1 row was checked by reading the code on both sides. Rows that weren't are marked "unverified".

**Checked and matching:**

**Summary**
1. Fix first (P0): the story share link points at a parked domain the app doesn't route (#1), web WebM voice notes likely won't play in iOS (#2), and stickers on web text stories are invisible in the app (#3).
2. Main P1 gaps on web: media-only moments (#4), gradient presets (#5), reels (#8), moment owners deleting comments (#9), report/block (#10), saved paging (#11). Shared-link previews and app links are broken by hosting config (#13-15).
3. Elsewhere: the app branch fixes UTC scheduling and the location/prompt display (#6, #7), backend story fixes are written but not deployed (#20) or still to do (#18, #19), and the unpushed web commits fix most story rendering but also delete all the web tests.
