## How web and app are connected today

The website (banatalk.com, a CRA SPA with partial prerendering, behind nginx) and the Flutter app are two clients of one backend (api.banatalk.com). They share accounts, JWTs, REST and Socket.IO. CORS allows both apex and www.

The app shares only `https://banatalk.com/{moment|profile|community}/<id>` (built by `shareUrl` in `link_constants.dart`) and invite links `https://banatalk.com/i/<code>`, which the backend builds. Story shares are the exception (#1). The web has a page for each of those paths and shows a mobile "Open in app" banner that tries `bananatalk://<type>/<id>`, then falls back to the store after 1.5 seconds.

iOS universal links work: the AASA file is valid through Apple's CDN and the team and bundle ids match. Android App Links are broken until real fingerprints replace the placeholders in assetlinks.json (#2).

Link previews only work if someone shares the backend URL `api.banatalk.com/og/...` directly. The real banatalk.com URLs always unfurl as the generic site card (#4). Referrals are wired end to end but switched off on the backend (`REFERRALS_ENABLED`), and a fresh install loses the invite code (#10). Emails link into the web, mostly to routes that don't exist (#9).

## Summary
- Broken now: story shares go to the parked bananatalk.com domain (#1), Android App Links can't verify because of the TODO fingerprints (#2), and https://www has no certificate (#3).
- Wrong or missing: the OG endpoint is unreachable from banatalk.com URLs, the repo's nginx config isn't applied, AASA claims `/chat/*` but the app ignores it, Flutter's built-in deep linking probably conflicts with `app_links`, the QR code uses a custom scheme, email CTAs go to dead routes, invite codes are lost on install, there's no Apple login on web, and the public profile leaks exact GPS.
- Owner actions: Play Console SHA-256 fingerprints, a www certificate, applying the nginx snippet plus a bot-to-/og rule, and checking `GOOGLE_PUBSUB_AUDIENCE` on prod. Everything else is a code change.
