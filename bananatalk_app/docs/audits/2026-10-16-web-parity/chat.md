# Web chat vs app/backend: contract audit (read-only)

Code audited:
- Web: `language_exchange_web_front/src` (working tree).
- App: `bt-integration/bananatalk_app` @ b65c9e3f.
- Backend: `be-integration` @ 232fb49.

Unpushed web commits (`origin/main..main`, 23 commits) contain no chat source changes. They only delete chat unit tests (`ChatContent*.test.tsx`, `useSocket*.test.tsx`, `chat*Endpoints.test.ts`, and others). Every finding below therefore also exists on origin/main, but the tests that covered this code are gone locally.

Paths: web = `src/...`, backend = `be/...`, app = `app/lib/...`.

Verified OK, no action needed:
- Conversation list (`GET /conversations?page&limit`).
- Thread pagination (`/messages/conversation/:a/:b?page&limit`, page 1 = newest).
- Text, sticker and GIF send, over the socket (`sendMessage {receiver,message,messageType}`) and the REST fallback (`type` is accepted).
- Media upload (`attachment` field) and voice (`/messages/voice`, `voice` field).
- Reply (`/:id/reply {message,receiver}`) and forward (`{receivers[]}`).
- Reactions, translate, TTS, vocabulary save, and corrections (REST and the `messageCorrection` socket event).
- Read receipts (`markAsRead {senderId}`, which triggers `messagesRead {readBy}`) and typing (`typing`/`stopTyping {receiver}`, which trigger `userTyping`/`userStoppedTyping {userId}`).
- Presence (`userStatusUpdate`, `presence:*`), the theme (`themeChanged`, keyed by conversation id), and pin/mute/delete conversation URLs.
- No web chat call hits a removed route, so there is no 404 risk.

## Summary
- Three P0s break chat between web and app users. Web message edits always return 400 (`content` vs `message`). Web "delete for everyone" only deletes for the web user (query param vs body field). Opening a chat from web posts a visible "Conversation started" message to the app user, which also counts against the 5-message first-chat limit.
- Web renders several app or backend message types badly: call history and location show as "File", waves are giant sticker text or appear on the wrong side, and story shares or replies lose their context. Web also hides every limit, paywall and block error behind a generic "Failed", and can send a message twice when the socket ack is slow.
- List and sync drift: deleted conversations come back because the list merges a raw-message feed, unread badges stick at 1, and there is no catch-up after a socket reconnect. iOS playback of WebM voice notes from web is the top item to test on a device. None of the findings come from the 23 unpushed commits, which only delete the chat tests.
